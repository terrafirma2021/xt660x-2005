# Engineering-unit derivation

This pass supplies executable arithmetic, converted cell values and nominal speed axes in [physical_units.json](physical_units.json), generated by [decode_units.py](../../scripts/decode_units.py). Every one of the 71 maps has a record. The subsequent [consumer pass](MAP_CONSUMERS.md) established 60 numeric/logical/conditional cell interpretations. The subsequent [temperature profile](TEMPERATURE_PROFILE.md) adds two explicitly conditional sensor conversions, and the [normalization review](NORMALIZATION.md) assigns the two inverse-ratio input-code interpretations: 64 numeric/logical/conditional conversions and seven joint arithmetic descriptions. The normalization codes are not newly established AFR or physical units. All 90 input-axis uses have a separate coordinate and remaining-requirement review in each dossier. This count does not mean every physical unit is confirmed. A numeric interpretation can be a code or threshold, not a physical tuning unit. Nominal speed axes cover 40 maps; conditional temperature axes cover 14 maps. The raw byte catalogue remains the storage authority.

There are three separate claims: **instruction-proven arithmetic**, **physical conversions conditional on named hardware assumptions**, and **unresolved hypotheses**. The catalogue preserves those distinctions and enables no tuning export. A conversion into milliseconds does not describe all corrections or establish an operating limit.

## Clock and diagnostic timing

At `0x5057–0x5059`, the application writes `5` to timer control register `0x004D`. In the [NXP MC9S12T64 manual](https://www.nxp.com/docs/en/data-sheet/9S12T64AF16V1.pdf), ECT TSCR2 prescaler setting `101` divides the bus clock by 32. The supplied application does not establish the inherited oscillator/PLL setup; the boot region is absent.

The scheduler at `0x679C` advances every 2,500 timer ticks. Every fourth update flags the task that dispatches the actuator tests. Fan diagnostic `0xBB45` starts an activation every 250 such tasks and holds its output for 100 task samples. Therefore:

```
fan repeat interval = 2500 * 4 * 250 = 2,500,000 timer ticks
fan active window   = 2500 * 4 * 100 = 1,000,000 timer ticks
```

Yamaha's [XT660 service manual](https://scootertuub.nl/motoren/Yamaha/Yamaha%20XT%20660%20R%20X%202004%20Service%20Manual%20%20.pdf), diagnostic 51, specifies five repetitions with two seconds on and three off. That independently supports **500 kHz timer / 2 µs ticks / 16 MHz bus** as the intended profile. It is not an oscillator measurement on this ECU. The injector diagnostic's 50-task spacing is then one second. Execution fixtures verify the divider, five repetitions and fan active windows, including 16-bit timer wrap.

## RPM and period limits

The capture logic counts eleven intervals with one double-length gap. It halves the gap interval for normalized history; six normalized pitches form `0x0A44`. Interpreting one pattern as one crank revolution gives twelve nominal pitches per revolution: 30° per pitch, 180° for the six-pitch period and 90° for the three-pitch period at `0x0A36`. This interpretation still needs independent rotor confirmation; the second-injector code does not establish it.

For period `P` ticks spanning `theta` crank degrees:

```
rpm = timer_hz * theta / (6 * P)
nominal six-pitch period: rpm = 15,000,000 / P
```

The recovered reciprocal calculation uses 37,500 and a Q8 fraction, then shifts three bits. In its verified non-overflow input range, the ideal code scale is:

```
speed_code = min(0xFE00, 8 * floor(37500 * 256 / P))
nominal rpm coordinate = speed_code * 100 / 512
```

For example, code 4096 is nominally 800 rpm and a code step of 512 is 100 rpm. Reciprocal truncation introduces a downward error of less than 1.5625 rpm before saturation under this profile. Saturated or stale/fault speed values must not be treated as fresh measurements. Existing tests exhaust periods 1200–65535; the equation is not a claim about pathological smaller periods.

The main cut's `P <= 2054` and resume's `P >= 2055` correspond nominally to approximately **7302.82 rpm** and **7299.27 rpm**. The conditional pair 1578 / 1595 corresponds to approximately 9505.70 / 9404.39 rpm. Use the exact comparison operators in [RPM_AND_CUTS.md](RPM_AND_CUTS.md); these thresholds describe different gates, not one universal limiter.

## Fuel durations and common normalization

The three 16-bit main quantity surfaces occupy a timer-duration domain through their correction chain to injector requests. Under the nominal clock, a raw cell is `raw * 0.002 ms` before corrections. It is neither a measured fuel mass nor a demonstrated AFR target. The injection-compensation curve at pointer `0x4234` contributes its selected byte times eight ticks: nominally `raw * 0.016 ms`.

Three previously omitted 2×2 maps are now extracted and tested with asymmetric synthetic cells to prove row/column orientation:

| Cells | Row / column inputs | Consumer |
|---|---|---|
| `0x311E–0x3121` | Speed / processed load | `0x0CD2` |
| `0x312A–0x312D` | Speed / throttle | `0x0CD3` |
| `0x321C–0x321F` | Combined normalization code / processed load | `0x0CD5` |

At `0x7EE4`, ROM `0x3114 == 0x80` selects `CD2`; every other value selects `CD3`. It is an equality comparison, not a bit test. Stock `0x3114` is zero. The selected code is combined with `CD4` as `CD0 = clamp(selected + CD4 - 128, 0, 255)`.

With `c=CD0`, `g=CD5`, and `r=ROM[0x1ACE]`:

```
denominator = floor(((c + 128) * (2*g) + 128) / 256)
if c == 0 or g == 0 or r == 0 or denominator == 0:
    CE2 = 256
else:
    CE2 = min(65535, floor((floor((r+128)*65536/denominator)+128)/256))
CE4 = min(65535, floor(quantity_0952 * CE2 / 256))
```

The same multiplier produces CE6, CE8 and CEA for the other quantity results. Stock constant cells `166`, gain `128`, reference `166`, and neutral `CD4=128` give `CE2=256`, or unity. Gain cell 128 is 100% **of the denominator**. Increasing it tends to reduce the resulting fuel multiplier. No evidence yet justifies renaming these codes AFR.

Other downstream stages still matter: centered additive correction, several gain products, mode selection, a blend with weights `998` and `255-998`, limits and additive pulse compensation. A raw base-cell duration is not the final output pulse.

Normal-running IAT curve `0x3220` contributes `(cell+384)/512`; its startup consumer uses a different stage scaling. Transient IAT curve `0x351D` contributes `(cell+384)/256`. Coolant curves `0x3345` and `0x3357` multiply their respective transient contributions by `cell/256`, with downstream signed encoding/clamps. These percentages are not interchangeable or universal percentages of total injected fuel.

## Spark and dwell

The final spark code `A82` is scheduled using this exact tick arithmetic at `0x54F0`:

```
advance_ticks = max(0, min(65535, floor(A82*A36/256) + A8B) - 150)
```

Under the twelve-pitch crank interpretation, A36 spans 90°, giving **0.3515625 relative crank degrees per code**. The catalogue exports relative scheduler degrees, **not degrees BTDC**. The physical TDC/reference angle is absent from the established evidence. The manufacturer's stock idle timing is only one operating point; using it to invent a universal offset would ignore correction and mode paths.

The speed correction curves at `0x4F64` / `0x4F81` contribute A8B in single timer ticks (nominal 0.002 ms per cell), followed by the fixed 150-tick subtraction. They are not fixed-degree corrections: a time correction changes its crank-angle effect with RPM.

The base dwell grid at `0x4B12` contributes `cell*32` ticks, nominally **0.064 ms per cell**, into A98. An additional A9C contribution and period-dependent limits produce A96. This is not a direct instruction to hold a coil for the uncorrected cell duration.

The [scheduler derivation](SPARK_SCHEDULER.md) now proves the ordinary event-relative equation and minimum-charge intervention, with 74,832 independent-model execution checks.

## Sensor conversions and conditional profiles

Diagnostic payloads alone do not establish dashboard display units. Exact payload calculations are tested separately from proposed physical labels.

| Signal | Proven firmware calculation | Remaining physical issue |
|---|---|---|
| Pressure | `min(254, floor(max(adc_left-7872,0)*256/49792))` | Assuming half-kPa diagnostic units suggests `(adc_left-7872)/389 kPa`, consistent with the manual's atmospheric voltage, but display scaling and reference voltage remain unverified. C90 includes further load processing. |
| Supply | `min(254, floor(adc_high*256/240))` | Not proven decivolts. Candidate `adc_high*5/64 V` agrees with a nominal 12 V replacement value and plausible dwell-axis range; analog divider is unconfirmed. |
| Throttle | Ten-bit ADC minus learned baseline, clamped at zero and shifted left six | Candidate `raw/512` degrees relative to learned closed position needs display/mechanical confirmation. It is not throttle percent. |
| Temperature | Sensor tables, then diagnostic `min(149,floor(raw*160/256))` | Conditional `0.625*raw-30 °C` profile now has reproducible resistance checks and variant tests. TDM fallback values agree; the XT coolant fallback specification differs. See [temperature evidence](TEMPERATURE_PROFILE.md). |

The temperature contradiction is material: the candidate formula would put fan-on at the first code above 217, or 106.25°C, but that is **not a verified Celsius fan threshold**. Choosing a different offset just to match the fallback would also need evidence. Pressure, supply and throttle remain unassigned hypotheses. Temperature values are now supplied only with the explicit candidate-profile requirement; they are not verified board units.

## Validation and model correction

[Execution results](units_variant_validation.json) compare independently written arithmetic and branch expectations against the compiled instruction translation. These tests caught an upstream model error: immediate `ADCB` read A instead of B. The corrected model uses B; previously generated normalization and other multiword arithmetic using that instruction are superseded. ADC indexed-A/direct-B forms also now use the shared carry-aware flag macro. New instruction fixtures vary A independently from B for every immediate-ADCB site in this image.

The processor model, raw p-code, structured C, complete C translation and Ghidra archive have been regenerated. Tests cannot establish board wiring, oscillator rate, sensor electronics or absolute crank phase. See [variant findings](VARIANTS.md) and [instruction evidence](variant_units_evidence.txt).
